# Changelog

## Unreleased

- Monitoring module (phase 1): one merged list of checks and alerts that Overview and the alert pipeline read, with Uptime Kuma and Grafana as the first two providers (`GET /api/monitoring`). A source that stops answering keeps its last known problems, is shown as unreachable, and raises one alert after two failed reads in a row; it is never shown as "all clear". Existing YAML-configured installs behave as before. Design: `docs/superpowers/specs/2026-11-26-monitoring-module-design.md`.
- Connect almost any software (monitoring phase 4): a **Custom HTTP source** (any address; GET or POST; bearer, basic, header or query sign-in; optional self-signed HTTPS; read the answer as a JSON list of checks, a JSON list of alerts, a Prometheus `/metrics` page, or just "does it answer"), **Service checks** (homedash probes HTTP, TCP ports and certificate expiry itself), and a **custom mapping for webhooks** so any JSON payload can be read. **Ready-made templates** for Healthchecks.io, Zabbix, Uptime Robot (API v2), Netdata and Checkmk are plain configuration checked against each tool's documentation; adding a tool means adding data, not code. Prometheus and Alertmanager sources can accept a self-signed certificate. See `docs/MONITORING.md`, "Connect anything".
- Your most used: homedash learns, per person, which pages and service tiles they open most and shows them on Overview. A page counts after a few seconds on it, a repeat within 30 seconds is ignored, and the score fades with a 30 day half-life. Only an id is stored (never a URL or content), each person sees only their own list, "Clear my history" wipes it, and the connect-a-source gallery lists the kinds you have connected before first. Web only for now.
- Monitoring module (phase 2): connect sources from the browser, no YAML and no restart. New page **Alerts & sources** and **Connect** buttons on Setup. Kinds: Uptime Kuma, Grafana, Prometheus (or compatible), Alertmanager, any JSON endpoint, and a webhook for any tool that can send a web request (Alertmanager and Grafana payloads and a simple `{name, status}` are understood). Sources are tested before they are saved, secrets are stored sealed and never shown again, and a source set in YAML always wins. The webhook receiver is the first route outside the login: hashed secret, constant-time check, uniform 401, rate limits, and the token hidden in homedash's own log. Guide: `docs/MONITORING.md`. Mobile: a read-only Monitoring screen.
- Dialogs keep keyboard focus inside while open and give it back when closed (all dialogs, not only the new one). The connect form names what is still missing, submits with Enter, refuses the same address twice, asks before replacing a webhook secret, and does not close the one-time secret screen on Escape. The CPU, memory and network cards say "No metrics source yet" instead of an error when Grafana is connected without its Prometheus data source ID.
- Grafana alert state: firing alert rules appear on Overview and raise alerts through the existing routes, silences and channels.
- ntfy inbox: the alert topic is read back and shown on the Notifications page and in the mobile app (needs a token that can read the topic).
- Alert deliveries and monitoring problems are written to the persisted event log (Logs, Events, source "alert" or "monitor").
- First-run polish: Overview says "Not connected" for integrations that are not set up instead of showing zeros; the login footer shows the real protocol; unknown addresses show a way back; copy buttons say "Copied"; larger tap targets on phones.

## 1.0.0 - 2026-11-26

- Fix: a server with no Proxmox settings at all (a first Docker run, or an install that is not finished) answered every request, sign-in included, with "No cluster". It now starts, lets you sign in, and shows "Not set up yet" with the Setup checklist.
- `homedash-config doctor`: tries every configured address and folder (Proxmox with the token, Grafana, Kuma, Loki, alert services, LLM agents, backup and data folders, Node version, secrets file mode) and explains each failure in plain words with the fix. A dead cluster member is only a warning while another answers.
- API reference generated from the running server (`GET /api/admin/openapi.json`, administrators): every route, its path parameters and the lowest role that may call it.
- Project support: troubleshooting guide and FAQ, issue and pull request templates, a release workflow (GitHub release plus a container image on ghcr.io on a version tag), a CI job that builds and runs the Docker image, a corrected contributing guide, and a community-scripts submission page. The README install command now points at this repository until the script is accepted upstream.
- Backups and audit page: run and list backups of homedash's own data with restore steps, verify the audit chain in one click, and download the trail (JSON lines or CEF).
- Services layout export and import: save order, pins, view and colour to a file and load it on another browser or install (validated, size-limited).
- Mobile app: sign in with an API token, so accounts with two-step sign-in or single sign-on can use it.
- Setup page for administrators: a live checklist (Proxmox reachable, HTTPS, two-step sign-in, alerts, self-backup, service-password encryption, a second administrator) with how to fix each gap, and every optional integration with the exact YAML to switch it on. The Overview reminds administrators until it is done. Scenes, schedules, routes and maintenance windows declared in `homedash.yaml` show an "In config" badge instead of buttons that would fail.
- Accessibility: a skip-to-content link, avatar and callout colours that meet contrast in both themes, and automated axe checks. Phone layout: stat cards and list rows no longer push the page sideways.
- Fixes from a full browser pass: CrowdSec no longer crashes when it is not set up, Services is always in the menu so the first service can be added from the UI, integrations that are not switched on say so instead of showing an error, and an unknown address no longer draws two pages. Browser smoke tests (Playwright) now run in CI.
- Services dashboard: 11 more service kinds (Sonarr, Radarr, Lidarr, Prowlarr, qBittorrent, Plex, AdGuard Home, Traefik, Immich, Nextcloud, UPS via NUT), an Add service form with a Test button and sealed secrets, Find services (probes your running guests for known apps), logos, response sparklines, pinning, drag-to-arrange, a launcher view, accent colours, wall mode and a per-user saved layout.
- Built-in HTTPS from your own certificate files (renewals picked up without a restart) or a self-signed one; installable app (PWA with icons and an offline shell, never caching API data); optional new-version notice with the `update` hint.
- Node upkeep: pending package updates (flagging a new kernel) and ZFS pool health (degraded, faulted, nearly full) are read hourly per node, alert once and recover, and show under `/api/cluster/upkeep`.
- Self-backup: `server.backup_dir` writes a consistent copy of homedash's own database on a schedule (mode 0600, newest N kept), with `GET/POST /api/admin/backups` to list and run one. Failures alert.
- Proxmox Backup Server tile (datastore fullness, failed tasks in the last 24 h, datastores that fill within 30 days).
- Public status page (`status_page:`): `/status` and `/status.json`, no sign-in, shows only the tiles and Uptime Kuma monitors you list as operational / degraded / outage, escaped, script-free and rate limited.
- CI: server tests, shipped-example validation, stricter shellcheck and syntax checks on every push and pull request.
- Service tiles: read-only status cards for Docker, Portainer, Pi-hole (v5 and v6), Nginx Proxy Manager (with certificate expiry), Jellyfin, Home Assistant and any JSON endpoint, declared under `tiles:`. A tile that stays unreachable raises one alert and one recovery.
- Tamper-evident audit trail: every audit row is hash-chained; `GET /api/admin/audit/verify` checks it, `/api/admin/audit/export` downloads it (JSON lines or CEF), and `audit:` pushes each new row to a syslog collector (UDP/TCP, RFC 5424) or an HMAC-signed webhook.
- Config as code: scenes, schedules, alert routes and maintenance windows declared under `policy:` are created, updated and removed to match the file at every start, and are read-only in the UI.
- Clusters: HA state on the Cluster page (master, agents, fencing, services) with alerts for fencing, dead agents, failed services and lost quorum; a migration pre-flight (local disks, passthrough, target RAM) that blocks what would fail and is enforced by the API; kernel-error alerts now cover every node of a cluster, read through the Proxmox API.
- Clusters: guests from every node of a Proxmox cluster, several API addresses per cluster with failover, several clusters or stand-alone nodes with a switcher, a Cluster page (nodes, quorum, load), live/restart migration, node-offline and quorum alerts, and per-node host pages, shutdown and metrics. Single-node installs behave as before.
- Incident tools: PagerDuty (Events API v2) and Opsgenie open an incident per problem and close it when the recovery arrives. Monitors and the Proxmox API now have stable keys so their recoveries close their own incident.
- Maintenance windows (one-off or weekly, per kind or text) and alert routing rules (by kind, severity, text, time of day), with a one-click silence from any alert.
- Access control: teams (per-guest scope by id range or tag), group-to-role/team mapping from OIDC groups and SCIM 2.0 (Users and Groups), live deactivation, personal API tokens, four-eyes approvals for risky actions, passkeys (WebAuthn), and an Access page with people, sessions, tokens and approvals.
- Alert channels: Gotify, Discord, Slack, Telegram, e-mail (SMTP), Apprise and a JSON webhook next to ntfy. Alerts fan out to every channel that is set up; each channel has its own on/off, minimum level and test button on the Notifications page, and every delivery is recorded per channel.
- `homedash.yaml` and `homedash-config` (validate, apply, status): one file switches integrations on and renders `.env`, nginx vhosts and add-on files (Alloy, Loki, Prometheus, CrowdSec snapshot, Grafana provisioning). nginx directories are configurable.
- Sign-in with any OpenID Connect provider (`OIDC_*`; `KEYCLOAK_*` still works), role mapping for SSO users.
- Roles (viewer, operator, admin), TOTP two-step sign-in with recovery codes, request rate limits, idle session timeout, per-account lockout counters.
- New pages: CrowdSec, Data manager (7 database engines), LLM server, Loki log analytics; GPU mining guard and QEMU device APIs.
- Host scripts: `tools/pve/host-addons.sh` (new), `create-token.sh` now creates a privilege-separated, read-only token by default.
